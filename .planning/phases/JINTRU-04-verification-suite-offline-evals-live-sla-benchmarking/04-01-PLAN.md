<task id="04-01-01">
<title>Create monotonic budget and SLA timeout escalation tests (`backend/tests/unit/test_budget.py`)</title>
<description>
Create `backend/tests/unit/test_budget.py` to exhaustively test the deadline clock, stage timeout allocations, and the 2.5s minimum synthesis window guard in `VerificationPipeline`:
1. Test that `RequestBudget` correctly tracks elapsed time against `REQUEST_DEADLINE_SECONDS` (8.0s).
2. Test that Stage 1 search timeout allocation is calculated as `min(2.0, remaining_time)`:
   - When remaining time is 7.5s, search timeout is capped at 2.0s.
   - When remaining time is 1.2s, search timeout is clamped to 1.2s.
3. Test that Stage 2 counter-search is skipped whenever `remaining_time < 3.5s`, preserving time for synthesis.
4. Test that `_enforce_synthesis_guard` strictly aborts when remaining time drops below 2.5s:
   - Raises `ProviderTimeoutError(message="Insufficient remaining budget for structured model synthesis", code="SYNTHESIS_WINDOW_EXCEEDED")`.
   - Dispatches zero model provider calls.
   - Persists zero rows to SQLite (leaving database completely clean).
5. Test that when synthesis times out, the pipeline cleanly propagates `ProviderTimeoutError` with HTTP 504 status mapping.
</description>

`backend/.venv/bin/pytest backend/tests/unit/test_budget.py -v` passes cleanly.

<task id="04-01-02">
<title>Create SQLite WAL multi-task concurrency stress test (`backend/tests/integration/test_concurrency.py`)</title>
<description>
Create `backend/tests/integration/test_concurrency.py` to verify multi-task concurrency and WAL durability:
1. Initialize a `Database` instance backed by a temporary file path on disk (testing real OS SQLite locks).
2. Launch 10 simultaneous asynchronous worker tasks (`asyncio.gather(*tasks)`):
   - Each worker performs a mixed randomized loop of 50 operations:
     - `save_verification()` with realistic `VerificationResponse` objects.
     - `get_verification()` reading back stored verifications.
     - `list_verifications()` querying paginated history and filtering by verdict.
     - `delete_verification()` deleting specific records.
3. Verify that `PRAGMA busy_timeout = 5000;`, `PRAGMA journal_mode = WAL;`, `PRAGMA synchronous = NORMAL;`, and the bounded exponential write retry loop (`_with_write_retry`) prevent lock failures.
4. Assert that exactly 0 `sqlite3.OperationalError: database is locked` or `database is busy` exceptions are raised across all 500 total concurrent database operations.
5. Verify data consistency: all successfully saved rows that were not deleted can be retrieved and decoded without JSON parse errors.
</description>
<verification>
`backend/.venv/bin/pytest backend/tests/integration/test_concurrency.py -v` passes cleanly.
</verification>
