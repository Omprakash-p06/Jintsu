<objective>
Establish the typed, tested boundary between the existing Next.js 16 workbench and the Phase 2 FastAPI gateway: fix the prototype's broken toolchain, add a single typed API client, and proxy `/api/v1` to the backend.

Purpose: Satisfies `UI-01` — "Next.js 16 + React 19 + TypeScript + stable Tailwind CSS v4 frontend application integration with typed API client (`frontend/lib/api.ts`)" — and removes the two defects that currently make the prototype unbuildable (`@/lib/utils` missing, `typescript.ignoreBuildErrors: true`).
Output: runnable `pnpm`/`npm` toolchain, `frontend/lib/api.ts`, `frontend/lib/utils.ts`, `/api/v1` rewrite, and a documented backend-origin env contract.

<prerequisites>
**Node runtime floor:** `next@16.4.3` declares `engines.node >= 20.9.0`; this workspace currently has Node `v18.19.1`. Dependency installation and `tsc --noEmit` work on Node 18, but `next build` / `next dev` will refuse to run. Task 3 therefore gates the build on the detected Node version and requires the executor to report the build as **blocked** (never as passing) when the floor is not met.
</prerequisites>
</objective>

<task type="auto">
  <name>Task 2: Typed API client mirroring the backend contracts</name>
  <files>frontend/lib/api.ts (Create)</files>
  <action>
    Create `frontend/lib/api.ts` as the only place the UI talks to the backend. Mirror `backend/app/api/schemas.py` field-for-field; do not invent fields the backend does not return.

    1. Types:
       ```ts
       export type PublicVerdict =
         | 'supported' | 'contradicted' | 'mixed' | 'insufficient_evidence' | 'not_verifiable'
       export type SourceStance = 'supports' | 'refutes' | 'neutral'
       export type Relevance = 'direct' | 'indirect' | 'contextual' | 'irrelevant'

       export interface SourceItem {
         source_id: string; url: string; domain: string; title: string; snippet: string
         stance: SourceStance; source_family_id: string; retrieved_at: string
         published_at: string | null; source_type: 'search_snippet' | 'llm_context'
         content_hash: string; extraction_status: 'ok' | 'truncated' | 'empty'
         is_quarantined: boolean; relevance: Relevance | null; exact_quote: string | null
       }
       export interface ReasoningStatement {
         statement: string; citation_ids: string[]; quoted_excerpt: string | null
       }
       export interface VerificationResponse {
         id: string; claim: string; public_verdict: PublicVerdict; summary: string
         limitations: string[]; sources: SourceItem[]; reasoning: ReasoningStatement[]
         created_at: string
       }
       export interface VerificationListItem {
         id: string; claim: string; public_verdict: PublicVerdict; created_at: string
       }
       export interface PaginatedVerificationResponse {
         items: VerificationListItem[]; total: number
       }
       export interface HealthResponse { status: string; providers: Record<string, string> }
       export interface ErrorEnvelope { error: string; code: string; detail: string | null }
       ```
    2. Error type:
       ```ts
       export class ApiError extends Error {
         constructor(readonly status: number, readonly code: string, message: string,
                     readonly detail?: string | null) { super(message); this.name = 'ApiError' }
       }
       ```
       Add `export function isApiError(value: unknown): value is ApiError` for the UI's error branch.
    3. Base URL: `const API_BASE = process.env.NEXT_PUBLIC_API_BASE_URL ?? '/api/v1'` — same-origin by default so the Next rewrite (Task 3) carries the request; an absolute base is supported for deployments that bypass the rewrite.
    4. A single private `request<T>(path, init)` helper that:
       - sets `Content-Type: application/json` when a body is present, `Accept: application/json` always;
       - aborts via `AbortController` after `CLIENT_TIMEOUT_MS = 12_000` (the backend's SLA is 8.0s; the client timeout is a backstop against a hung socket, never the primary budget) and converts an abort into `new ApiError(0, 'CLIENT_TIMEOUT', 'The request exceeded the client timeout.')`;
       - on `response.status === 204` returns `undefined as T`;
       - on non-2xx parses the body as `ErrorEnvelope` (tolerating a non-JSON body) and throws `ApiError(status, envelope.code ?? \`HTTP_${status}\`, envelope.error ?? response.statusText, envelope.detail)`;
       - parses and returns JSON otherwise.
    5. Public functions:
       ```ts
       export const createVerification = (claim: string) =>
         request<VerificationResponse>('/verifications', { method: 'POST', body: JSON.stringify({ claim }) })
       export const listVerifications = (params?: { limit?: number; offset?: number; verdict?: PublicVerdict }) =>
         request<PaginatedVerificationResponse>(`/verifications${toQuery(params)}`)
       export const getVerification = (id: string) =>
         request<VerificationResponse>(`/verifications/${encodeURIComponent(id)}`)
       export const deleteVerification = (id: string) =>
         request<void>(`/verifications/${encodeURIComponent(id)}`, { method: 'DELETE' })
       export const purgeVerifications = () => request<void>('/verifications', { method: 'DELETE' })
       export const getHealth = () => request<HealthResponse>('/health')
       ```
       `toQuery` must omit `undefined` values and `encodeURIComponent` every value.
    6. Do not add caching, retries, or client-side persistence; the backend owns the record.
  </action>
  <verify>
    <automated>cd frontend && npx tsc --noEmit && grep -q "export class ApiError" lib/api.ts && grep -c "request<" lib/api.ts</automated>
  </verify>
  <done>
    `lib/api.ts` exports the schema-mirroring types, `ApiError`, the predicate, and the six endpoint functions; `tsc --noEmit` passes with the module included.
  </done>
</task>

<task type="auto">
  <name>Task 3: Same-origin /api/v1 proxy and toolchain gate</name>
  <files>frontend/next.config.mjs (Modify), frontend/.env.example (Create)</files>
  <action>
    1. `frontend/next.config.mjs`:
       - Delete `typescript: { ignoreBuildErrors: true }` — it is the reason a broken prototype could still "build", and both the roadmap criterion and AGENTS.md require real type checking.
       - Keep `images: { unoptimized: true }`.
       - Add a rewrite so the browser talks only to its own origin:
         ```js
         async rewrites() {
           const backend = (process.env.JINTRU_API_URL ?? 'http://127.0.0.1:8000').replace(/\/$/, '')
           return [{ source: '/api/v1/:path*', destination: `${backend}/api/v1/:path*` }]
         }
         ```
         Server-side only, so the backend origin is never baked into the client bundle.
    2. Create `frontend/.env.example` documenting both knobs with their defaults and a one-line note each:
       - `JINTRU_API_URL=http://127.0.0.1:8000` — backend origin used by the Next rewrite (server side).
       - `NEXT_PUBLIC_API_BASE_URL=/api/v1` — leave at the default to go through the rewrite; set an absolute URL only when the browser must call the backend directly.
    3. Toolchain gate — detect the Node version before claiming a build:
       - If `node -v` is ≥ 20.9.0: run `npm run build` and require exit 0.
       - If it is below 20.9.0 (as in this workspace, v18.19.1): do **not** run or simulate a build; verify `tsc --noEmit` and the rewrite export, and record in the SUMMARY that `next build` is blocked by the Node engine floor with the exact versions. Never report the build as passing.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Next rewrite -> FastAPI | Untrusted client input crosses into the backend gateway |
| Backend error bodies -> UI | Server-provided error text crosses into the rendered page |
| Package registry -> build | Third-party packages are installed and bundled |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Spoofing | `next.config.mjs` rewrite target | medium | mitigate | Backend origin comes from server-side `JINTRU_API_URL` only; no client-visible absolute origin and no wildcard destination |
| T-03-02 | Information Disclosure | `lib/api.ts` error handling | medium | mitigate | Surface `ErrorEnvelope.code`/`message` only; never echo request bodies, headers, or stack traces into the UI |
| T-03-03 | Tampering | API payload trust | high | mitigate | All responses are typed at the boundary and unknown fields are ignored, so a compromised backend cannot inject UI state outside the declared contract |
| T-03-04 | Repudiation | Zero-telemetry invariant | medium | mitigate | Remove `@vercel/analytics` entirely rather than leaving it disabled behind a flag |
| T-03-05 | Denial of Service | Client hang on a stalled socket | low | mitigate | 12s `AbortController` backstop converts a hung fetch into `CLIENT_TIMEOUT`, above the backend's 8.0s SLA so it never masks a real 504 |
| T-03-SC | Tampering | Dependencies | high | mitigate | No new runtime dependencies added; install only from the existing lockfile manifest and keep Tailwind on stable `^4.3.3` |
</threat_model>
