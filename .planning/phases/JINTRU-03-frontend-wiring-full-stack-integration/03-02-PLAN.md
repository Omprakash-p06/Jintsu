       - Guard `claim.trim().length < 5 || claim.trim().length > 500 || loading`.
       - Set `error = null`, `loading = true`, start a `setInterval(100ms)` updating `elapsedMs` and clearing it in `finally` (also clear on unmount via `useEffect` cleanup).

    3. Progress stages — the endpoint is synchronous and streams nothing, so the stage list is **time-estimated, and the UI must say so**:
       - Stages in backend order: `Classifying claim`, `Searching evidence`, `Seeking counterevidence`, `Synthesizing`, `Validating citations`, `Saving record`.
       - Advance by elapsed thresholds aligned to the real budget (0.2s classify, 2.3s search, 2.0s counter-search, 3.0s synthesis, then validate/persist); mark the current stage with `aria-current="step"`, completed stages with a check icon **and** the word "done" in visually-hidden text.
       - Render the elapsed timer as `mm:ss` with `aria-live="off"` (a ticking value must not spam a screen reader); put the progress container in `role="status"` with a static sentence.
       - Add a caption: "Stages are estimated; the backend completes the whole verification in a single request."
    4. Error alert: render when `error` is set, above the claim panel — `role="alert"`, icon + `error.message`, the code in `.alert-code`, optional `detail`, and a dismiss button. Map the known codes to human copy: `PROVIDER_TIMEOUT`/`SYNTHESIS_WINDOW_EXCEEDED` → "Verification exceeded the 8-second budget and was aborted."; `VALIDATION_ERROR` → the claim violated the 5–500 character contract; `PROVIDER_UNAVAILABLE` → "A search or model provider is unavailable."
    5. Keep the character counter (`{claim.length} / 500` with `.near-limit` at >450), disable the textarea and button while loading, and keep the Ctrl/Cmd+Enter shortcut wired to `verify`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend payload -> rendered DOM | Model-authored summary, limitations, and third-party snippet text cross into the page |
| Stored record -> restored view | A previously persisted record is re-rendered without re-verification |
| Browser -> external source site | Evidence links leave the application origin |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-06 | Tampering | `SourceCard` snippet rendering | high | mitigate | Render text through React's default escaping only — no `dangerouslySetInnerHTML` anywhere in the file; the snippet is untrusted third-party text |
| T-03-07 | Spoofing | Quarantined source presentation | high | mitigate | `is_quarantined` sources are visibly marked and carry no outbound link, so injected content cannot be presented as verified evidence |
| T-03-08 | Tampering | Outbound evidence links | medium | mitigate | Every external anchor uses `target="_blank"` with `rel="noopener noreferrer"`; empty URLs render no anchor at all |
| T-03-09 | Information Disclosure | Telemetry / client bundle | medium | mitigate | No analytics or logging of claim text; only `NEXT_PUBLIC_*` values reach the bundle |
| T-03-10 | Denial of Service | Destructive history actions | medium | mitigate | Purging requires explicit confirmation, and a failed delete/purge leaves the list unchanged with a visible error |
| T-03-SC | Tampering | Dependencies | high | mitigate | No new runtime dependency is introduced; icons come from the already-installed `lucide-react` |
</threat_model>
