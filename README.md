# Reality Check AI (`jintru`) — Verifiable Claim Verification System

Reality Check AI is a clock-bounded empirical claim verification engine designed to evaluate factual assertions through multi-stage dialectical retrieval, strict verbatim citation entailment, and deterministic application-level verdict policy enforcement.

---

## 1. System Overview and Core Principles

Reality Check AI evaluates single empirical assertions within an authoritative **8.0-second monotonic SLA deadline**. Unlike conventional retrieval-augmented generation (RAG) systems that blindly trust model summaries or lack verification rigor, the architecture incorporates strict algorithmic boundaries:

1. **Clock-Bounded Monotonic Budgeting:** Every asynchronous retrieval, filtering, and synthesis operation executes against a monotonic 8.0s ceiling. Subordinate stage timeouts clamp to remaining time; requests abort cleanly with an HTTP 504 `SYNTHESIS_WINDOW_EXCEEDED` if fewer than 2.5s remain.
2. **Gate A Conservative Pre-Retrieval Screening:** Regex and temporal heuristics screen non-empirical assertions (subjective value judgments and future prospective predictions) in under 10 milliseconds, bypassing downstream search and synthesis costs.
3. **Dialectical Two-Stage Retrieval:** Executes affirmative evidence search in Stage 1, followed by targeted counter-evidence search in Stage 2 to discover conflicting or refuting evidence.
4. **Strict Verbatim Citation Entailment:** Quotes generated by LLM synthesis must match retrieved snippet text verbatim (with zero-width character stripping and HTML unescaping). Ungrounded quotes and invalid citations are stripped.
5. **Deterministic Verdict Policy Matrix:**
   - **Absence of Counterevidence Guardrail:** Strictly prohibits a `supported` verdict when credible, relevant refuting evidence exists in retrieved sources.
   - **Multi-Family Corroboration:** Requires at least two independent source family domains (normalizing publisher subdomains and wire services such as AP, Reuters, and PR Newswire) to award `supported`.
   - **Grounding Constraints:** Prohibits `contradicted` verdicts without direct refutation and `mixed` verdicts without both supporting and refuting evidence.

## 3. Quickstart: Setup and Execution

### Prerequisites
- Python >= 3.11
- Node.js >= 20.9.0 and pnpm >= 9.0

### Option A: Cross-Platform Universal Python Scripts (Recommended)

The setup and run scripts are implemented in standard Python and run natively across Windows, macOS, and Linux without shell dependencies:

```bash
# 1. Install dependencies and initialize environment
python setup.py

# 2. Start both backend and frontend services
python run.py
```

### Option B: Makefile (POSIX / Linux / macOS)

```bash
make setup    # Run setup.py
make dev      # Run run.py (starts backend and frontend)
```

### Option C: Containerized Deployment (Docker Compose)

```bash
docker compose up --build
```

### Endpoints
- **Frontend Workbench:** http://localhost:3000
- **REST API Gateway:** http://localhost:8000/api/v1
- **Interactive OpenAPI Documentation:** http://localhost:8000/docs
- **Health Check Endpoint:** http://localhost:8000/api/v1/health

## 5. Configuration Reference (`.env`)

A default `.env` file is initialized from `.env.example` during setup. When `USE_MOCK_PROVIDERS=true`, the system runs fully offline without requiring external API keys:

```bash
# --- Provider Mode ---
# Set to 'true' for local deterministic mocking (no external API keys needed).
# Set to 'false' to enable live Brave Search and Meta/OpenAI model providers.
USE_MOCK_PROVIDERS=true

# --- Brave Search API ---
# Required if USE_MOCK_PROVIDERS=false. Obtain from https://brave.com/search/api/
BRAVE_API_KEY=
BRAVE_RETRIEVAL_MODE=snippets    # "snippets" or "context"

# --- LLM Provider (Meta AI / OpenAI-compatible) ---
# Required if USE_MOCK_PROVIDERS=false
META_API_KEY=
META_API_BASE_URL=https://api.meta.ai/v1
META_MODEL=muse-spark-1.3

# --- Storage & Performance ---
DATABASE_PATH=data/jintru.db
REQUEST_DEADLINE_SECONDS=8.0
CACHE_ENABLED=true
```

## 7. Technical Hardening and Architectural Improvements

Recent hardening measures implemented across the codebase:

1. **Modular Verification Engine:** Decomposed the monolithic verification service into discrete, testable components (`screening.py`, `clustering.py`, `citations.py`, `policy.py`, `cache.py`, and `verification.py`), preserving 100% backward compatibility while isolating stage logic.
2. **Universal Cross-Platform Runner:** Implemented standard Python setup and execution scripts (`setup.py` and `run.py`) providing zero-dependency native execution on Windows, macOS, and Linux with automated health checking and signal handling.
3. **Persistent Query Caching:** Added `QueryCache` to cache search results with TTL expiration, eliminating redundant network calls for identical queries and mitigating rate-limit exhaustion.
4. **Content Security Policy and HTTP Security Headers:** Configured strict headers (`Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`) in Next.js.
5. **Python 3.11+ Support:** Relaxed `requires-python = ">=3.11"` in `backend/pyproject.toml` to support standard enterprise Linux environments.
